Votre intranet BBI peut ressembler à un vrai site web — voici comment.

0Synthèse exécutive — 60 secondes

Votre intranet actuel est fonctionnel mais « enfermé » dans les gabarits SharePoint : la page d'accueil s'affiche dans une zone de contenu étroite, encadrée par la barre de suite Microsoft, l'en-tête de site et la navigation du hub. Résultat : environ 30 % de la hauteur d'écran est consommée avant le premier contenu utile, et l'ensemble lit comme « un site SharePoint », pas comme « le site BBI ».

Les 5 décisions qui changent tout

🖥️

1 · Accueil en page applicative

Convertir accueil.aspx en SingleWebPartAppPage : plus d'en-tête, plus de navigation, plus de titre de page. Un héros de 100 % de la hauteur visible, bord à bord.
📐

2 · Extension « BBI Plein écran »

Un Application Customizer supprime les marges résiduelles du canevas, expose la charte en variables CSS et n'agit que sur les pages applicatives.
🧭

3 · Navigation dans la page

La barre de navigation devient partie intégrante du site (logo, ancres, recherche, CTA) au lieu d'être imposée par le hub.
🖼️

4 · Galerie médias native

Une bibliothèque d'images + une web part BBI Galerie médias (albums, visionneuse plein écran accessible) : la vie d'entreprise devient visible.
🗂️

5 · Contenu provisionné par script

Listes, colonnes, vues, pages et web parts créées par un script idempotent : zéro saisie manuelle, zéro écart entre le design et la réalité.
🏷️

Bonus · Marque cohérente

Thème « BBI Bleu nuit », logo, en-tête, pied de page et (option) police institutionnelle via le Brand center.

2« Page plein écran, comme un vrai site web » — la réponse honnête

Votre demande initiale : « je veux la page d'accueil complètement pleine page, même masquer la barre de navigation SharePoint, plein écran comme un site web, y compris dans le workbench ». Voici les trois routes possibles, ce qu'elles donnent réellement, et ce que nous recommandons.

RouteCe que vous obtenezCe que vous ne pouvez pas avoirSupport Microsoft
A · Page applicative
LIVRÉ		 Plus d'en-tête de site, plus de navigation, plus de titre, plus de barre de commandes. Contenu bord à bord, héros 100 % écran, ancres, recherche dans la page. La barre de suite Microsoft (waffle, recherche, avatar) reste visible : elle appartient au cadre M365, pas au site. Natif & supporté — SingleWebPartAppPage + supportsFullBleed.
B · CSS « pirate » Masquage visuel de la barre de suite. Rien de fiable : casse à chaque mise à jour SharePoint, brise la recherche/notifications, non supporté, risque de sécurité perçu. Interdit par Microsoft (personnalisation du cadre M365 non supportée). Nous ne le livrons pas.
C · Teams / Viva Connections
LIVRÉ		 Zéro chrome SharePoint : la page est rendue dans Teams (onglet personnel ou expérience Viva). Idéal formateurs mobiles, tablette en salle. Il faut Teams installé ; l'apparence dépend du client Teams. Natif & supporté — mêmes web parts, hôte Teams déclaré dans les manifestes.
⚠️ Le point qu'il faut assumer — « 100 % sans aucune barre Microsoft » n'est pas atteignable dans un navigateur sans hack non supporté. La combinaison A + C vous donne : navigateur = expérience plein écran propre, sans en-tête SharePoint ; Teams/Viva = écran réellement intégral. C'est le maximum défendable, et celui que nous avons implémenté.

2.1 · Comment ça marche techniquement (les 4 leviers)

  1. Déclarer le web part « full page » et « full bleed » dans son manifeste : 
    "supportedHosts": ["SharePointWebPart", "TeamsTab", "SharePointFullPage", "TeamsPersonalApp"],
"supportsFullBleed": true
  2. Basculer la page en page applicative : 
    # PnP PowerShell
Set-PnPClientSidePage -Identity "accueil.aspx" -LayoutType SingleWebPartAppPage
    Ou via l'interface : Pages du site → page → Type de mise en page.
  3. Supprimer les marges résiduelles du canevas avec l'extension livrée (BbiFullScreenApplicationCustomizer). Elle détecte le type de la page par API, n'agit que sur les pages applicatives, et expose la charte en variables CSS (--bbi-navy, --bbi-red…). Elle redimensionne les web parts après coup.
  4. Calculer un héros réellement plein écran : la web part mesure la hauteur réelle du chrome au-dessus d'elle et la publie en --bbi-chrome-offset, puis se dimensionne en calc(100vh - var(--bbi-chrome-offset)). C'est ce qui fait que ça marche aussi dans le workbench (où le chrome est bien plus haut qu'en production).
🧪 Workbench — depuis SPFx 1.20+, il n'existe plus de workbench local : on teste dans le workbench hébergé du tenant (/_layouts/15/workbench.aspx). La mesure de chrome et le bord-à-bord ont été conçus pour ce contexte : pas de « saut » visuel entre le test et la page publiée.

5.3 · Pièges à éviter

  • Accents et espaces dans les noms de colonnes → les noms internes divergent. Le script les fixe explicitement (InternalName).
  • Colonne Album non renseignée → tous les médias tombent dans « Tous les albums ». C'est le premier réflexe éditorial à donner aux équipes.
  • Images non optimisées → visez 1600–2000 px de large et < 300 Ko ; la galerie génère les vignettes à la volée.
  • Oublier les vues → sans vue « Prochaines sessions », la page affiche les sessions passées.
  • Renommer une liste après coup → mettez à jour le volet Propriétés des web parts (le titre est configurable, pas codé en dur).

Règles simples à faire respecter

1 · Le bleu nuit porte, le rouge souligne : jamais deux fois le rouge dans le même bloc.
2 · Un titre, une idée. Pas de phrase-titre de plus de 12 mots.
3 · Les photos montrent des personnes en action, pas des salles vides.
4 · Icônes en trait, jamais mélangées avec des emoji dans la même section.
5 · Contraste minimum 4,5:1 (AA) pour tout texte.

Typographie

Segoe UI (natif, disponible partout) en attendant l'installation de la police institutionnelle. Mise en œuvre du Brand center : téléverser la police (woff2/ttf, < 10 Mo), créer un jeu de polices (Titre / Corps), l'appliquer via ⚙️ → Modifier l'apparence → Police. Avantage : cohérence inter-sites, sans code.

Bibliothèque visuelle à constituer

10 à 15 photos haute définition (sessions, certifications, séminaires, portraits de formateurs), un jeu d'illustrations cohérent, le logo en PNG transparent (couleur + blanc). À ranger dans SiteAssets/marque/ — puis la galerie les diffuse.

6.1 · Ce qu'il faut verrouiller côté thème

  • Publier le thème « BBI Bleu nuit » au niveau tenant (Add-PnPTenantTheme / Brand center) et masquer les thèmes non conformes dans la galerie.
  • En-tête de site : Compact + Strong + logo BBI ; sur la page d'accueil applicative, l'en-tête est de toute façon masqué.
  • Pied de page du hub : mentions légales, RGPD, accessibilité, contact support.
  • Navigation du hub : Accueil · Catalogue · Espace formateurs · Actualités · Support (masquée automatiquement aux non-membres par le cache de sécurité).

7Qualité, performance & gouvernance

⚡ Performance

≤ 20 web parts par page · images < 300 Ko · gribouillage JS mesuré · Page Diagnostics for SharePoint > 75 · pas de web part lourde au-dessus de la ligne de flottaison. Le héros anime son image en CSS (pas de vidéo lourde), et la galerie charge ses vignettes en différé.

♿ Accessibilité

Structure de titres h1→h3 · focus visible partout · navigation clavier dans la visionneuse (Échap, ← →) · aria-modal et restitution du focus · prefers-reduced-motion respecté · contraste AA · cibles tactiles ≥ 44 px.

🔐 Sécurité documentaire

Modification confinée à l'espace de production · publication d'une copie verrouillée · étiquette de sensibilité « afficher uniquement » · accès conditionnel navigateur · journal d'audit. Le seul point non bloquable : la capture d'écran (à traiter par la sensibilisation + filigrane).

🧑‍⚖️ Gouvernance éditoriale

1 propriétaire par rubrique · revue trimestrielle du catalogue · SLA de publication à 3 jours ouvrés · relecture obligatoire pour les pages publiques · journal des évolutions par version.

📆 Rythme

Actualités : 1 à 2 par semaine · Galerie : après chaque temps fort · Catalogue : revue trimestrielle · KPI : revue mensuelle.

🧮 Indicateurs (objectif marque)

% de contenus à jour · taux de rebond sur l'accueil · temps avant premier clic · satisfaction via micro-sondage (« avez-vous trouvé ? ») · nombre de pages consultées par visiteur · mentions « intranet professionnel » en entretien collaborateur.

9.2 · Comportement à vide — garantie « aucune page cassée »

Le package se comporte comme un site en production dès la fin du déploiement : aucune page blanche, aucun message d'erreur technique, même si vous n'avez encore rien saisi. L'installation peut donc se faire en une seule fois, puis les contenus réels arrivent progressivement.

Web partSource surveilléeSi absente, non créée ou vide
BBI AccueilActualites, Sessions, FormateursActualités, sessions à venir et formateurs d'exemple, dates calculées relativement (jamais périmées)
BBI Catalogue des formationsFormations5 formations BBI représentatives, filtrables
BBI Fiche formationFormations, Sessions, Supports publiés, FormateursFiche complète (objectifs, programme, prérequis, sessions, supports, référent) — y compris pour un code inconnu
BBI Sessions & inscriptionsSessions, FormationsPlanning de 6 sessions réparties sur les mois à venir, filières renseignées
BBI Article d'actualitéActualitesArticle rédigé, visuel embarqué, 3 actualités liées
BBI Galerie médiasGalerie médias8 photos dans 4 albums (4 visuels embarqués au format 1400 px)
BBI Documents sécurisésSupports publiés4 supports ; le bouton d'ouverture est neutralisé (aucun appel à un fichier inexistant)

Le basculement se fait source par source : vous pouvez publier les actualités avant les sessions, l'accueil reste cohérent à chaque étape. Un bandeau « données de démonstration » peut être affiché pendant la mise en place via l'option showDataNotices (masquée par défaut dans les manifestes).

Prochaine étape recommandée — déployer le package puis exécuter .\provision-bbi-intranet.ps1 -SiteUrl <votre site> -DryRun pour visualiser le plan de provisionnement, puis la même commande sans -DryRun. La page d'accueil est présentable immédiatement ; remplacez ensuite les contenus de repli par vos contenus réels, bloc par bloc. Comptez une demi-journée pour la mise en service, hors réglages de conformité (étiquettes, IRM) qui relèvent de votre administrateur Purview.
