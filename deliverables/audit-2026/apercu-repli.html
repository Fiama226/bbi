Ce que voit un collaborateur quand aucune donnée n'existe encore

Aperçu rendu avec les feuilles de styles compilées des composants réellement livrés et les visuels embarqués dans le package. Dans SharePoint, ce rendu est identique : listes absentes, non créées ou vides donnent le même résultat. Aucune donnée réelle n'a été utilisée pour cette page.

Le principe. Chaque web part interroge sa liste ou sa bibliothèque. Trois cas mènent au contenu de repli : source absente (404), source non créée, source créée mais vide. Dans les trois cas la page reste complète et crédible ; dès qu'un premier élément réel est publié, il remplace les exemples de son bloc, sans intervention technique et sans recharger la page.
Vérifié automatiquement. Le harnais bbi-intranet/tools/verify-fallback.js exécute 42 contrôles sur les couches de données du package, contre un client SharePoint simulé : source absente, source vide, source alimentée. Les trois cas sont couverts pour l'accueil, le catalogue, la fiche formation, les sessions, l'article, la galerie et les documents.

À retenir. Le contenu de repli est un filet de sécurité, pas le produit : l'objectif reste que vos listes Actualites, Sessions, Formations, Formateurs, Supports publiés et Galerie médias soient alimentées. L'option showDataNotices permet d'afficher un bandeau pendant la mise en place pour suivre ce qu'il reste à remplir, puis d'être désactivée pour la mise en production.
